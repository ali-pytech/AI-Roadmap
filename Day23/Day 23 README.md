# Day 23 — Encapsulation & Abstraction in Python OOP

Today I mastered **Encapsulation and Abstraction**, the final pillars of Object-Oriented Programming.  
- **Encapsulation** secures data by restricting direct access and using getters/setters.  
- **Abstraction** hides complexity and enforces structure using abstract classes.  

---

## Projects I Built

###Iqama Encapsulation
- Private attribute `__fee` with getter/setter methods.  
- Ensures fee updates are validated before applying.

###VAT Invoice Abstraction
- Abstract base class `Transaction` defines a contract.  
- Child class `Invoice` implements `summary()` to calculate VAT totals.

###Housing Encapsulation
- Private attribute `__monthly_rent` with controlled access.  
- Prevents invalid rent updates.

###Student Abstraction
- Abstract base class `Person` enforces `role()` method.  
- `Student` and `Teacher` implement role differently.

###Shopping Cart Encapsulation
- Private attribute `__price` with getter/setter.  
- Subtotal depends on encapsulated price.



##Reflections
- **Encapsulation** protects sensitive data and ensures safe updates.  
- **Abstraction** enforces consistency and hides unnecessary details.  
- Together, they make systems **secure, clean, and professional**.  
- My repo now shows **all four OOP pillars** (Classes, Inheritance, Polymorphism, Encapsulation, Abstraction).
